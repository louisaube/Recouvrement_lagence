# Demande à l'API : versions de politique (import JDM, contrôles d'activation, activation)

Écrans demandeurs : Imports (onglet « Politique », dépôt et feu vert) et Politique (versions, contrôles, témoins, activation). Besoin : importer une version datée de la politique, en voir les contrôles d'activation et les résultats des dossiers témoins, l'activer ; lire la version active. Pas d'éditeur de politique : un fichier se dépose, il ne se modifie jamais.

## Opérations
Toutes les routes : garde de profil `supervisor` (`profils-api-modification-request.md`) ; la politique n'est jamais lisible par un autre profil, ni par un compte agent. Listes : `from` 0 à 2147483647, `size` 1 à 100 (défaut 10), réponse `{ items, total }`.

| Méthode et chemin | Action déclarée | Rôles | Entrée (bornes comprises) | Réponses (codes et formes) |
|---|---|---|---|---|
| `GET /policy-versions` | `policies:list` | profil `supervisor` | `status` facultatif : `imported` \| `active` \| `superseded` ; `from`, `size` | `200 { items: PolicyVersionDto[], total }`, de la plus récente `versionDate` à la plus ancienne, puis `importedAt` décroissant |
| `GET /policy-versions/:id` | `policies:get` | profil `supervisor` | `id` uuid | `200 { version: PolicyVersionDetailDto }` ; `404 repository.not_found` ; `400` id mal formé |
| `POST /policy-versions/previews` | `policies:preview` | profil `supervisor` | `multipart/form-data`, une partie `file` : JSON UTF-8, 2 097 152 octets au plus | `200 PolicyPreviewDto` ; `400 policies.invalid_file_type` (pas du JSON) ; `409 policies.already_imported` (même empreinte déjà importée) ; `413 policies.file_too_large` |
| `POST /policy-versions/previews/:previewId/confirm` | `policies:confirm` | profil `supervisor` | `previewId` uuid | `201 { version: PolicyVersionDto }` ; `404 policies.preview_not_found` ; `409 policies.invalid_file` ; `409 policies.already_imported` |
| `POST /policy-versions/:id/activate` | `policies:activate` | profil `supervisor` | `id` uuid ; aucun corps | `200 { version: PolicyVersionDto }` ; `404 repository.not_found` ; `409 policies.activation_blocked` (corps avec `details: { path: <code du contrôle>, reason }[]`) ; `409 policies.not_activatable` (version déjà active ou remplacée) |

Aucune route de modification ni de suppression d'une version (`PUT`, `PATCH`, `DELETE` répondent `404`).

DTO :
- `PolicyVersionDto` = `{ id, label: string(1..100), versionDate: date, status: 'imported' \| 'active' \| 'superseded', fileHash: string(64) /* SHA-256 hexadécimal */, importedBy: { id, email }, importedAt, activatedBy: { id, email } \| null, activatedAt \| null, checksPassed: boolean \| null }` (`checksPassed` : résultat des six contrôles à l'instant de l'import pour une version `imported`, `null` sinon).
- `PolicyCheckDto` = `{ code: 'floor' \| 'decreasing_concessions' \| 'counterparts' \| 'schedule_limits' \| 'segments_covered' \| 'witnesses', passed: boolean, problems: string(1..300)[] /* au plus 50, français, vides si passed */ }`.
- `PolicyWitnessResultDto` = `{ id: string(1..50), description: string(1..200), expected: { action, rule }, obtained: { action, rule } \| null, passed: boolean }`.
- `PolicyRuleDto` = `{ segment, nature: 'family' \| 'company', horizonDays, nextStep: { kind: 'external_collector' \| 'litigation' \| 'assignment', expectedValueBp }, ladder: PolicyRungDto[], maxScheduleDays, thresholdCents, requiredDocuments: ('contract' \| 'order' \| 'delivery_proof')[], limitation: { delayDays, startsFrom: 'invoice_date' \| 'due_date', alertDays } }` ; `PolicyRungDto` = `{ rank: integer, offerKind: 'lump_sum' \| 'schedule', valueBp, payByDays, installments: { count, intervalDays } \| null, delayFeeBp, counterpart: { type: 'firm_date' \| 'first_payment' \| 'direct_debit', deadlineDays \| null, firstPaymentBp \| null } \| null }`.
- `PolicyGlobalDto` = `{ statementMaxAgeDays, ledgerMaxImports, reviewSampleSize, paymentMethods: string[], decisionTypeCapsBp: { none, reminder, proposal, transfer_proposed }, exposureCeilings: { agentVersion: string, segment: string, maxCents }[] }`.
- `PolicyVersionDetailDto` = `PolicyVersionDto` + `{ global: PolicyGlobalDto, rules: PolicyRuleDto[], checks: PolicyCheckDto[] /* recalculés à la lecture, sans écriture */, witnesses: PolicyWitnessResultDto[] }`.
- `PolicyPreviewDto` = `{ previewId, fileName, fileHash, valid: boolean, errors: { path: string(1..200), reason: string(1..300) }[] /* au plus 100, chemin JSON */, label: string \| null, versionDate: date \| null, global: PolicyGlobalDto \| null, rules: PolicyRuleDto[], checks: PolicyCheckDto[], witnesses: PolicyWitnessResultDto[] }` ; si `valid` est faux, `checks`, `witnesses` et `rules` sont vides.

Trace d'audit : `confirm` et `activate` sont tracées (types d'objet « Version de politique » ; actions `policies:confirm` et `policies:activate` ; identifiant = id de la version ; résumés « Version de politique « <label> » du <JJ/MM/AAAA> importée. » et « … activée. » sans contenu du fichier). L'aperçu est exempté (aucune écriture métier).

## Format du fichier de politique (format pivot)
Objet JSON strict (toute clé inconnue est une erreur), UTF-8 :
- `label` (chaîne 1 à 100), `versionDate` (`AAAA-MM-JJ`), `decision` (graphe JDM de GoRules ZEN, objet), `parameters`, `witnesses`.
- `decision` est évaluée par `@gorules/zen-engine`. Entrée : `{ segment, nature, state, daysLateMax, negotiableCents, overThreshold }` (`state` parmi les états du dossier, `daysLateMax` entier ≥ 0 : retard de la plus en retard des factures négociables). Sortie : `{ action: 'none' \| 'reminder' \| 'proposal' \| 'transfer_proposed', rule: chaîne 1 à 100 }`. Aucune correspondance : action `none`, règle `no_rule`.
- `parameters.global` : `statementMaxAgeDays` (0 à 3650), `ledgerMaxImports` (1 à 100 : nombre d'imports de créances après lequel une sortie approuvée non constatée passe en écart), `reviewSampleSize` (1 à 10 000), `paymentMethods` (1 à 20 codes `^[a-z][a-z0-9_]{0,29}$`), `decisionTypeCapsBp` (pour chacune des quatre actions, plafond de part dans un lot, 0 à 10 000 points de base), `exposureCeilings` (0 à 500 plafonds `{ agentVersion: chaîne `^[A-Za-z0-9._-]{1,50}$` ou `*`, segment ou `*`, maxCents }`).
- `parameters.rules` (1 à 1 000 entrées, une par couple segment et nature, couple unique) : `segment` (`^[a-z0-9][a-z0-9_-]{0,49}$`), `nature` (`family` \| `company`), `horizonDays` (1 à 3650), `nextStep { kind, expectedValueBp }` (0 à 10 000 : valeur attendue de l'étape suivante en part du montant négociable ; c'est le plancher), `ladder` (1 à 20 offres, de la plus favorable à la moins favorable), `maxScheduleDays` (0 à 3650), `thresholdCents` (0 à 10 000 000 000), `requiredDocuments`, `limitation { delayDays (1 à 36500), startsFrom, alertDays (0 à 36500) }`. Offre de l'échelle : `offerKind`, `valueBp` (0 à 10 000 : somme à payer en part du montant négociable), `payByDays` (0 à 365 : délai du premier paiement depuis le jour de l'offre), `installments { count (2 à 60), intervalDays (1 à 365) }` (obligatoire pour `schedule`, absent pour `lump_sum`), `delayFeeBp` (0 à 10 000, frais ou intérêt sur un délai, défaut 0), `counterpart` ({ `type`, `deadlineDays` (1 à 365, pour `firm_date`), `firstPaymentBp` (1 à 10 000, pour `first_payment`) }).
- `witnesses` (1 à 200) : `{ id (1 à 50, unique), description (1 à 200), input: <entrée de la décision sans overThreshold>, expected: { action, rule } }`.
- Durée d'une offre à échéancier : `payByDays + (count − 1) × intervalDays`.

## Règles
- `rule-recouvrement-policy-versioned` (user) : une version de politique est datée (`versionDate`), importée puis activée par un superviseur identifié (`importedBy`, `activatedBy`) ; l'empreinte SHA-256 du fichier est conservée ; un même fichier (même empreinte) n'est importé qu'une fois (`409 policies.already_imported`).
- `rule-recouvrement-policy-immutable` (user) : une version active n'est jamais modifiée ; l'activation d'une nouvelle version fait passer l'ancienne à `superseded` dans la même transaction ; une version `superseded` n'est plus activable (`409 policies.not_activatable`) ; il y a au plus une version active (garanti par un index unique partiel de la base).
- `rule-recouvrement-policy-format` (user) : la politique est une décision JDM évaluée par `@gorules/zen-engine`, accompagnée de ses paramètres et de ses dossiers témoins, dans le fichier pivot ci-dessus. Un fichier qui ne respecte pas le format (JSON invalide, clé inconnue, borne dépassée, graphe JDM que le moteur refuse de charger, couple segment-nature en double, identifiant de témoin en double) a `valid: false` avec ses erreurs ; sa confirmation répond `409 policies.invalid_file`.
- `rule-recouvrement-policy-no-business-value-in-code` (user) : aucune probabilité, aucun taux, aucun montant, aucun délai, aucun seuil ni aucune liste (moyens de paiement, pièces, segments) ne vient d'ailleurs que du fichier de politique en vigueur ou d'un fichier importé ; le code n'en porte aucun.
- `rule-recouvrement-policy-activation-checks` (user) : l'activation exécute les six contrôles, tous bloquants, sur le contenu de la version et les créances confirmées à cet instant ; au moindre échec `409 policies.activation_blocked` et rien n'est modifié. Les contrôles sont affichés à l'aperçu, à la lecture d'une version et à l'activation.
- `rule-recouvrement-policy-floor` (user) : contrôle `floor` : pour chaque règle, `valueBp` de chaque offre de l'échelle est supérieur ou égal à `nextStep.expectedValueBp` (le plancher du segment) ; une offre sous le plancher échoue.
- `rule-recouvrement-policy-concessions-decreasing` (user) : contrôle `decreasing_concessions` : dans chaque échelle, `valueBp` décroît strictement d'une offre à la suivante et l'écart entre deux offres successives diminue ; le cas de deux écarts égaux relève de la règle dédiée ci-dessous. Une échelle d'une ou deux offres satisfait le contrôle de l'écart.
- `rule-recouvrement-concessions-equal-gaps` (inferred, default Q-RECOUVREMENT-10) : deux écarts successifs égaux (par exemple 100 %, 90 %, 80 %) font échouer le contrôle `decreasing_concessions` : chaque écart doit être strictement inférieur au précédent. (Option B : un écart égal est accepté.)
- `rule-recouvrement-policy-counterparts` (user) : contrôle `counterparts` : toute offre à partir de la deuxième (chaque concession) porte une contrepartie complète (`firm_date` avec `deadlineDays`, `first_payment` avec `firstPaymentBp`, ou `direct_debit`) ; la première offre (l'ancrage) peut n'en avoir aucune.
- `rule-recouvrement-policy-schedule-limits` (user) : contrôle `schedule_limits` : aucune offre n'a une durée supérieure à `maxScheduleDays` ; pour la nature `family`, aucune offre à délai (`payByDays` > 0 ou `schedule`) ne porte `delayFeeBp` > 0.
- `rule-recouvrement-policy-segments-covered` (user) : contrôle `segments_covered` : chaque couple (segment, nature) présent dans les créances confirmées (dossiers non soldés) a une règle ; les couples manquants sont nommés dans `problems`. Sans créances confirmées le contrôle réussit.
- `rule-recouvrement-policy-witnesses` (user) : contrôle `witnesses` : chaque dossier témoin, évalué par le moteur, donne exactement `expected` (action et règle) ; les écarts sont listés avec la valeur obtenue.
- `rule-recouvrement-policy-supervisor-only` (user) : la politique, le plancher et les offres non débloquées ne sont lisibles que par le profil `supervisor` ; aucune réponse destinée à un compte agent n'en contient une trace.
- `rule-recouvrement-policy-json-not-spreadsheet` (inferred) : le mécanisme d'import du socle n'accepte que `.xlsx` et `.csv` (nature du fichier vérifiée avant lecture) ; la politique, fichier JSON, suit un parcours à deux temps propre (aperçu sans écriture métier, conservé 2 heures et privé à son créateur ; confirmation) qui reproduit les garanties du socle (atomicité avec la trace, doublon refusé).
- `rule-recouvrement-policy-audited` (inferred) : la confirmation et l'activation sont tracées, jamais l'aperçu ni les lectures.

## Compatibilité
Aucune opération existante modifiée. Tables nouvelles (versions, aperçus, témoins) : voir le plan du module. Le moteur `@gorules/zen-engine` est une dépendance nouvelle de `api/`. `specifications/permissions.yaml` : une ligne par opération, garde de profil.
