# Demande à l'API : outils des agents (REST et serveur MCP)

Écran demandeur : Fiche dossier (elle affiche offres débloquées, engagements, gels et décisions que ces outils produisent) ; la recette joue l'agent par ces outils, sur les deux transports. Besoin : huit outils par lesquels un agent de canal interroge le cerveau, sur une API REST et sur un serveur MCP qui n'en est que l'enveloppe. L'agent n'a aucune autorité propre : il ne reçoit que des conditions, jamais un motif interne. Aucun message n'est envoyé et aucun modèle de langage n'est appelé.

## Contexte commun à chaque appel
Authentification par jeton porteur d'un compte au profil `agent` (garde de profil `agent`). Pour chaque appel REST, en-têtes obligatoires :
- `X-Agent-Version` : `^[A-Za-z0-9._-]{1,50}$` ;
- `X-Channel` : `voice` \| `email_sms` \| `mail`, égal au canal du compte (`403 agent.channel_mismatch` sinon) ;
- `X-Conversation-Id` : `^[A-Za-z0-9._:-]{1,100}$` (pour l'ouverture, l'identifiant choisi par l'agent ; pour les autres outils, celui d'une conversation ouverte) ;
- `Idempotency-Key` : `^[\x21-\x7E]{1,128}$`.
Un en-tête absent ou mal formé : `400 agent.missing_context` (avant toute autre vérification métier, après l'authentification et la garde de profil). Pour MCP, ces quatre valeurs sont les arguments `agentVersion`, `channel`, `conversationId`, `idempotencyKey` de chaque outil.

## Opérations REST
| Méthode et chemin | Action déclarée | Rôles | Entrée (bornes comprises) | Réponses (codes et formes) |
|---|---|---|---|---|
| `POST /agent/conversations` | `agent:open-conversation` | profil `agent` | corps strict `{ caseId: uuid, interlocutorId: uuid, aiDisclosureGiven: boolean }` | `201 AgentConversationDto` ; `403 agent.ai_disclosure_required` (`false`) ; `404 cases.not_found` ; `409 agent.interlocutor_unreachable` ; `409 agent.conversation_exists` |
| `GET /agent/cases/:caseId` | `agent:read-case` | profil `agent` | `caseId` uuid | `200 { case: AgentCaseDto }` ; `404 cases.not_found` ; `404 agent.conversation_not_found` |
| `POST /agent/cases/:caseId/next-offer` | `agent:next-offer` | profil `agent` | corps strict `{ counterpart?: { type: 'firm_date' \| 'first_payment' \| 'direct_debit' } }` | `200 { status: 'offer', offer: AgentOfferDto }` ou `200 { status: 'exhausted', offer: null }` ; `409 negotiation.stopped` ; `409 offers.statement_stale` ; `409 offers.counterpart_required` ; `409 offers.counterpart_mismatch` ; `404` |
| `POST /agent/cases/:caseId/commitments` | `agent:register-commitment` | profil `agent` | corps strict `{ offerId: uuid, paymentMethod: string (1..30), totalCents: integer (1..10000000000), installments: { dueDate: date, amountCents: integer (1..10000000000) }[] (1 à 60) }` | `201 { commitment: AgentCommitmentDto, confirmationOrder: { id: uuid, status: 'planned' \| 'blocked' } }` ; `409 commitments.offer_mismatch` ; `409 commitments.offer_expired` ; `409 commitments.payment_method_not_allowed` ; `409 commitments.already_committed` ; `409 commitments.exposure_ceiling_reached` ; `409 negotiation.stopped` ; `409 offers.statement_stale` ; `404` |
| `POST /agent/cases/:caseId/contestations` | `agent:report-dispute` | profil `agent` | corps strict `{ reason: string (rogné, 1..1000), invoiceNumbers?: string[] (1 à 100 distincts, chacun 1..50) }` | `201 { contestationId: uuid, frozenInvoices: integer }` ; `404 contestations.invoice_not_found` ; `404` |
| `POST /agent/cases/:caseId/human-requests` | `agent:request-human` | profil `agent` | corps strict `{ reason?: string (rogné, 1..1000) }` | `201 { requestId: uuid }` ; `409 agent.human_request_not_available` ; `404` |
| `POST /agent/cases/:caseId/complaints` | `agent:report-complaint` | profil `agent` | corps strict `{ text: string (rogné, 1..1000) }` | `201 { complaintId: uuid }` ; `404` |
| `POST /agent/messages/check` | `agent:check-message` | profil `agent` | corps strict `{ caseId: uuid, text: string (1..5000) }` | `200 { allowed: boolean, violations: { code: 'amount_not_unlocked' \| 'date_not_unlocked' \| 'internal_term', excerpt: string(1..100) }[] }` (au plus 50) ; `404` |

Réponses communes : `401` (jeton absent ou invalide) ; `403 security.access_denied` (autre profil) ; `400 agent.missing_context` ; `409 agent.idempotency_conflict` (même clé avec une autre requête) ; `404 agent.conversation_not_found` (conversation inconnue, d'un autre compte ou d'un autre dossier, pour tout outil sauf l'ouverture) ; `400 api.validation.incoming_failed`.

DTO (vue de l'agent : jamais de segment, de plancher, de politique, d'offre non débloquée, de motif interne ni de rang dans l'échelle) :
- `AgentConversationDto` = `{ conversationId, caseId, interlocutorId, channel, openedAt }`.
- `AgentCaseDto` = `{ caseId, nature: 'family' \| 'company', interlocutors: { id, role, email: string \| null, phone: string \| null, postalAddress: string \| null }[] /* joignables sur le canal, seules les coordonnées utiles au canal renseignées */, invoices: { number, creditorSiren, balanceCents, dueDate }[] /* factures non gelées, non prescrites */, negotiableCents, currentOffer: AgentOfferDto \| null, commitments: AgentCommitmentDto[], allowedActions: ('next_offer' \| 'register_commitment' \| 'report_dispute' \| 'request_human_intervention' \| 'report_complaint' \| 'check_message')[] }`.
- `AgentOfferDto` = `{ id, totalCents, discountCents, installments: { dueDate, amountCents }[], counterpart: { type, deadlineDate: date \| null, firstPaymentCents: integer \| null } \| null }`.
- `AgentCommitmentDto` = `{ id, totalCents, paymentMethod, status: 'pending' \| 'held' \| 'broken', installments: { dueDate, amountCents }[] }`.

## Serveur MCP
`POST /mcp` : serveur MCP en HTTP en flux (Streamable HTTP) du SDK TypeScript officiel (`@modelcontextprotocol/sdk`), sans état de session. Même authentification porteur et même garde de profil `agent` que le REST (jeton absent : `401` HTTP ; autre profil : `403`). `GET /mcp` et `DELETE /mcp` répondent `405`. Huit outils, un par opération REST : `open_conversation`, `read_case`, `next_offer`, `register_commitment`, `report_dispute`, `request_human_intervention`, `report_complaint`, `check_message`. Chaque outil prend les arguments de son corps REST (plus `caseId` hors ouverture et vérification) et les quatre valeurs de contexte. Résultat : `structuredContent` = le corps de réponse REST ; refus : `isError: true` et `structuredContent` = `{ status, code, message }` identique au corps REST. Action déclarée : `agent:mcp`. Dans le contrat OpenAPI : une seule opération `POST /mcp` au corps JSON-RPC opaque.

## Règles
- `rule-recouvrement-agent-tools-only` (user) : le compte agent n'accède qu'aux outils des agents (routes `/agent/*` et `/mcp`), et seulement pour les dossiers ouverts à son canal ; il ne voit jamais la politique, le plancher, les offres non débloquées, le segment, le journal, ni les autres dossiers ; toute autre route répond `403 security.access_denied`.
- `rule-recouvrement-agent-authentication` (inferred, default Q-RECOUVREMENT-03) : le compte agent s'authentifie par la connexion du socle (`POST /auth/login` avec `returnToken: true`) et présente le jeton de 24 heures en jeton porteur ; il se reconnecte à l'expiration. (Option B : jeton d'agent longue durée créé par l'administrateur, affiché une fois, révocable.)
- `rule-recouvrement-agent-case-channel-access` (inferred, default Q-RECOUVREMENT-08) : un dossier est ouvert à un canal quand il n'est ni `settled` ni `transferred`, qu'au moins une de ses factures négociables autorise ce canal et que l'interlocuteur demandé y est joignable ; sinon `404 cases.not_found`, indiscernable d'un dossier inexistant. (Option B : seulement les canaux d'un ordre d'envoi du lot prêt du jour.)
- `rule-recouvrement-agent-context` (user) : chaque appel porte le compte agent, la version d'agent, le canal, l'identifiant de conversation et une clé d'idempotence ; un appel qui en manque est refusé (`400 agent.missing_context`).
- `rule-recouvrement-agent-calls-logged` (user) : chaque appel est journalisé avec ses entrées et sa réponse (table des appels : compte, version d'agent, canal, conversation, clé, outil, entrées, statut et corps de la réponse, instant), y compris les refus de statut inférieur à 500 ; ce journal n'est lisible d'aucun profil par l'API ; les écritures sont aussi tracées au journal d'audit (types « Appel d'agent » ; actions `agent:*` ; résumé sans texte libre ni coordonnée).
- `rule-recouvrement-agent-idempotency` (user) : un appel rejoué avec la même clé (même compte, même outil) rend la même réponse (statut et corps) sans nouvel effet, en-tête de réponse `Idempotent-Replayed: true` ; deux appels simultanés de même clé n'ont qu'un effet ; la même clé avec une requête différente donne `409 agent.idempotency_conflict`. La lecture est aussi soumise à la clé : rejouée, elle rend l'état enregistré.
- `rule-recouvrement-agent-two-transports` (user) : les mêmes opérations et les mêmes contrôles sur REST et sur MCP ; MCP appelle les mêmes services et n'a aucune règle propre ; un même scénario joué sur les deux transports donne les mêmes réponses (hors identifiants) et les mêmes effets.
- `rule-recouvrement-agent-ai-disclosure` (user) : ouvrir une conversation exige la déclaration que l'interlocuteur a été informé qu'il parle à une IA (`aiDisclosureGiven: true`) ; sans elle (`false`) `403 agent.ai_disclosure_required` et rien n'est enregistré ; aucun autre outil n'est accessible sans conversation ouverte avec cette déclaration (lecture comprise : `404 agent.conversation_not_found`).
- `rule-recouvrement-agent-read-case` (user) : la lecture rend les interlocuteurs joignables sur le canal, les factures non gelées et leurs soldes, le montant négociable, l'offre en cours (la dernière offre débloquée non remplacée ni révoquée), les engagements et les actions permises ; `allowedActions` exclut `next_offer` et `register_commitment` quand la négociation est arrêtée, que le relevé est périmé ou que l'échelle est épuisée.
- `rule-recouvrement-agent-no-internal-reason` (user) : aucune réponse destinée à l'agent ne contient la règle, la version de politique, le plancher, le segment, un rang d'échelle ou un montant de référence ; le motif interne reste au journal des décisions.
- `rule-recouvrement-offer-anchor` (user) : la première offre rendue est la première de l'échelle, chiffrée par le cerveau ; elle ne demande aucune contrepartie.
- `rule-recouvrement-offer-descend` (user) : l'agent descend l'échelle une offre à la fois, chaque concession contre sa contrepartie : à partir du deuxième appel, `counterpart.type` est obligatoire (`409 offers.counterpart_required`) et doit être celui de la contrepartie exigée par la concession suivante (`409 offers.counterpart_mismatch`, rien n'est débloqué) ; l'agent ne sort jamais de l'échelle.
- `rule-recouvrement-offer-exhausted` (user) : échelle épuisée, l'outil répond `{ status: 'exhausted', offer: null }` ; la négociation s'arrête, un élément `ladder_exhausted` entre dans la file (un seul) et le dossier passe à `supervisor_queue`. Rejoué avec une autre clé, l'outil répond de nouveau `exhausted` sans second élément.
- `rule-recouvrement-offer-computation` (inferred) : le cerveau chiffre l'offre à partir de la règle de la politique : somme = `valueBp × montant négociable / 10 000` (entier, arrondi à la moitié supérieure) plus, quand l'offre a un délai ou un échéancier, `delayFeeBp × montant négociable / 10 000` ; `discountCents` = max(0, montant négociable − somme) ; premier versement : jour de l'offre + `payByDays` ; échéancier en parts égales, reliquat de centimes sur la dernière, une échéance tous les `intervalDays` ; contrepartie `firm_date` : date = jour + `deadlineDays` ; `first_payment` : `firstPaymentBp × somme / 10 000` ; `direct_debit` : sans détail. La durée d'un échéancier ne dépasse jamais `maxScheduleDays` (garanti par le contrôle d'activation).
- `rule-recouvrement-offer-stale-statement` (user) : sans relevé bancaire frais, aucune offre n'est rendue (`409 offers.statement_stale`) et aucun engagement n'est inscrit.
- `rule-recouvrement-offer-exposure-ceiling` (user) : quand le plafond d'encours sous échéancier de la version d'agent et du segment est atteint (`rule-recouvrement-exposure-ceiling`), l'outil ne rend plus d'offre à échéancier : il répond `exhausted` sans ouvrir d'élément `ladder_exhausted` (une alerte s'ouvre, voir lot du jour) ; l'inscription d'un engagement à échéancier qui ferait dépasser le plafond est refusée (`409 commitments.exposure_ceiling_reached`).
- `rule-recouvrement-commitment-exact` (user) : un engagement précis (montant, date, moyen de paiement, échéances le cas échéant) reproduit exactement une offre débloquée du dossier (total, nombre d'échéances, dates, montants) ; sinon `409 commitments.offer_mismatch` ; une offre révoquée, remplacée par un engagement ou à première échéance passée : `409 commitments.offer_expired`.
- `rule-recouvrement-commitment-payment-method` (inferred) : `paymentMethod` appartient à la liste `paymentMethods` de la politique active (`409 commitments.payment_method_not_allowed`) ; aucun moyen n'est écrit dans le code.
- `rule-recouvrement-commitment-effects` (inferred) : l'inscription crée l'engagement `pending`, passe l'offre à `accepted` et les autres offres débloquées à `superseded`, porte le dossier à `committed`, journalise la décision, émet l'ordre `commitment_confirmation` et refuse un second engagement tant qu'un est `pending` (`409 commitments.already_committed`).
- `rule-recouvrement-commitment-figures` (user) : la réponse rend les chiffres que l'agent répète au débiteur (montant, échéances, moyen de paiement, remise) ; le texte de la confirmation écrite n'est pas produit ici (le cerveau émet l'ordre, voir `lot-du-jour`).
- `rule-recouvrement-contestation-stops-case` (user) : une contestation exprimée dans une conversation arrête la négociation de tout le dossier : gel de portée dossier `contestation`, litige créé par facture visée (origine `contestation`, pour le service litiges), gel de ces factures, élément de file `contestation`, état `frozen` ; les outils de négociation répondent ensuite `409 negotiation.stopped`.
- `rule-recouvrement-contestation-without-invoices` (inferred, default Q-RECOUVREMENT-06) : `invoiceNumbers` est obligatoire (au moins un numéro) : absent ou vide, `400 api.validation.incoming_failed` et rien n'est gelé. (Option B : absent, toutes les factures non gelées du dossier sont visées et `frozenInvoices` les compte.)
- `rule-recouvrement-human-request` (user) : l'outil « intervention humaine » suspend la négociation et place le dossier dans la file du superviseur (élément `human_request`, état `supervisor_queue`) ; il est pensé pour les familles.
- `rule-recouvrement-human-request-companies` (inferred, default Q-RECOUVREMENT-05) : pour une entreprise l'outil est refusé (`409 agent.human_request_not_available`) ; `allowedActions` n'y contient pas `request_human_intervention`. (Option B : accepté pour toute nature, mêmes effets.)
- `rule-recouvrement-complaint` (user) : une réclamation signalée est enregistrée (texte, conversation, version d'agent) et compte dans l'indicateur « réclamations / actions » ; elle ne change pas l'état du dossier.
- `rule-recouvrement-message-check` (user) : l'outil vérifie un texte avant envoi : chaque montant et chaque date du texte appartiennent aux conditions débloquées du dossier, et le texte ne contient aucun terme interne ; sinon `allowed: false` avec les violations motivées (`amount_not_unlocked`, `date_not_unlocked`, `internal_term`) et l'extrait fautif ; le texte n'est ni envoyé ni modifié.
- `rule-recouvrement-message-known-amounts` (inferred, default Q-RECOUVREMENT-11) : les montants et dates « débloqués » sont ceux des offres débloquées non révoquées (total, remise, échéances, premier versement, dates de contrepartie) et des engagements du dossier ; les soldes des factures ne le sont pas. (Option B : s'y ajoutent les soldes, le montant négociable et les échéances que `read_case` a rendus.)
- `rule-recouvrement-message-parsing` (inferred) : un montant est un nombre (séparateurs de milliers espace, espace insécable ou point, décimales avec virgule ou point, deux au plus) accompagné de `€`, `eur`, `euro` ou `euros` avant ou après ; un nombre sans devise n'est pas un montant. Une date s'écrit `JJ/MM/AAAA`, `JJ-MM-AAAA`, `JJ.MM.AAAA`, `AAAA-MM-JJ` ou `J mois AAAA` (mois en lettres françaises, `1er` accepté) ; sans année, jour et mois seuls sont comparés. Un terme interne est l'un des mots `plancher`, `règle`, `version`, `segment` (singulier ou pluriel, sans tenir compte de la casse ni des accents), reconnu en mot entier.
- `rule-recouvrement-agent-conversation-bound` (inferred) : une conversation est attachée à un dossier, un interlocuteur, un compte agent et un canal ; un outil appelé avec un dossier différent de celui de la conversation répond `404 cases.not_found`.
- `rule-recouvrement-agent-evaluation` (inferred) : chaque appel d'outil sur un dossier déclenche son évaluation (`rule-recouvrement-evaluation-points`) avant de répondre.

## Compatibilité
- Aucune opération existante modifiée. `@modelcontextprotocol/sdk` est une dépendance nouvelle de `api/`.
- La liste fermée des types de contenu du socle suffit (`application/json`). Le corps de `POST /mcp` est un message JSON-RPC : le contrat le déclare comme objet libre (borné à 1 Mio) ; le test de robustesse fondé sur le contrat ne doit y obtenir ni 500 ni réponse hors schéma.
- `X-Agent-Version`, `X-Channel`, `X-Conversation-Id`, `Idempotency-Key` sont déclarés comme paramètres d'en-tête requis de chaque opération `/agent/*` ; `Idempotent-Replayed` comme en-tête de réponse.
- `specifications/permissions.yaml` : une ligne par opération, garde de profil `agent`.
