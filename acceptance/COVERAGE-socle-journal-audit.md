# Coverage - version `socle-journal-audit`

Acceptance files (black box, HTTP + SQL seeding): `acceptance-audit-journal.test.ts` (reading, filters, filter options, immutability), `acceptance-audit-trace.test.ts` (traces left by the six foundation routes); shared helper `audit-helpers.ts` (reuses `scope-helpers.ts`). Previous suites are unchanged. `specifications/permissions.yaml` gains `GET /audit-logs` (`audit:list`) and `GET /audit-logs/filters` (`audit:filters`), admin only, `ownership: none`, so no `cross_owner_tests`. The six traced routes keep their entries.

Legend: API = covered by an acceptance test; UI = studio behaviour; "not observable" = no HTTP route exposes it to a black-box test.

Assumptions made by the tests (taken from the module plan and the API request, not contradicted by the user request): error bodies expose `code`; refusal of a role is `403 security.access_denied`; the journal table is `base.audit_logs` with columns `id`, `occurred_at`, `actor_id`, `actor_email`, `action`, `object_type`, `object_id`, `scope_code`, `summary` (used to seed entries with chosen dates and authors, to prove immutability and to inspect secrets); `base.credentials(user_id)`, `base.group_users(user_id)` and `base.users(id)` are used to delete an account by SQL (no delete route exists); object types are the French labels `Utilisateur`, `Groupe`, `Périmètre`; action codes are the `apiAction` of the traced routes; no route lets an account be deleted, so deletion-survival is shown with SQL.
