# Coverage - version `socle-import-excel`

Acceptance files (black box: HTTP including multipart, SQL seeding/inspection, files built by hand in `import-helpers.ts`): `acceptance-import-specification.test.ts`, `acceptance-import-preview.test.ts`, `acceptance-import-errors.test.ts`, `acceptance-import-confirm.test.ts`, `acceptance-import-large.test.ts` (300,000-row .csv, 200,000-row .xlsx, 100,000 duplicates, aborted analysis; timeout 600 s). Previous suites are unchanged.

`specifications/permissions.yaml` gains the four operations of the accounts import, all `allow: [admin]`. `specification` and `preview` are `ownership: none`. `errors` and `confirm` are declared `ownership: own` (deviation from the module plan §3.5, which wrote `none`): a preview belongs to the administrator who created it (`rule-foundation-import-preview-owner`), another administrator gets the same 404 as for an unknown id, and the two `cross_owner_tests` prove it. `allow` stays `[admin]` since the probe calls the routes without body and the guards answer 401/403 first.

Legend: API = covered by an acceptance test; UI = studio behaviour; "not observable" = no HTTP route exposes it to a black-box test.

Assumptions made by the tests (taken from the module plan and API request, not contradicted by the user request):
- Error bodies expose `code`; refusal of a role is `403 security.access_denied`; `409`/`404`/`413` codes are the `import.*` codes of §3.4.
- Temporary tables are inspected by SQL with the names and columns of the module plan: `base.import_previews(id, status, expires_at, created_count, skipped_count, confirmed_at)`, `base.import_preview_rows(preview_id)`, `base.import_preview_errors(preview_id)`. Expiry and the `analyzing` state are simulated by `UPDATE` on `import_previews`.
- The audit entry of a confirmation uses the module plan values (action `users:import-confirm`, object type `Import de comptes`, summary `Import de N comptes depuis « nom »`), not the earlier `user-import` of the API request (plan assumption 5.3); the confirm response also carries `fileName` (same assumption). One entry per import, not one per created account (plan assumption 4): the tests do not count the `users:create` entries.
- A `.xlsx` is accepted by extension and content; encrypted ZIP entries may answer `import.invalid_file_type` or `import.unsafe_archive`.
- Exact reason texts are those of module plan §3.2.3; the plural form of unknown groups and the placement of `…` are only checked by prefix.
- A completely empty line in a `.csv` is a blank record (number kept); a CSV without any header line is refused (`missing_columns` or `invalid_file_type`).
- The harness truncates every table of `base`, including the import tables, between scenarios.
