Les tests du socle ne doivent pas casser quand une version métier ajoute ses propres routes. Aujourd'hui, le test « [Q-PLAT-03] the OpenAPI document is served in test… » (api/src/features/auth/tests/auth.test.ts) exige la liste exacte des chemins du document OpenAPI, et refuse tout texte contenant « company », « tenant » ou « entreprise » dans tout le document : la première version métier (page « Mon compte ») l'a fait échouer. Le corriger pour qu'il vérifie que les chemins du socle sont tous présents, qu'aucun chemin de test (/test/) n'est servi et que les deux schémas de sécurité existent, sans interdire les chemins ni les mots ajoutés par les modules métier. Vérifier de même qu'aucun autre test du socle n'énumère exhaustivement les routes, les tables, les actions d'audit ou les entrées du menu de façon à interdire un ajout métier ; corriger ceux qui le font, sans affaiblir ce qu'ils vérifient sur le socle. Aucun changement de comportement, de contrat ni de droits.
